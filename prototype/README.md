# CDSS Research Prototype — Phase 09

> **⚠️ Research use only.** This prototype has not been validated for clinical diagnosis or emergency triage. Outputs do not replace assessment by a qualified healthcare professional.

## Overview

An interactive Clinical Decision Support System (CDSS) prototype that:
- Accepts symptoms from the **132-feature catalogue** used in Phases 00–08
- Returns **ranked disease candidates** (top-5) with calibrated probabilities
- Generates **SHAP local explanations** for any disease candidate
- Presents model provenance, validation metrics, and safety context

Built with **FastAPI** (backend) + vanilla **HTML/CSS/JS** (frontend, served by FastAPI).

## Quick Start

### Option A — Startup Script (recommended)

```bash
cd prototype/
bash start.sh
```

This creates a virtual environment, installs all dependencies, and launches the server.

### Option B — Manual

```bash
cd prototype/backend
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
uvicorn app.main:app --reload --host 0.0.0.0 --port 8181
```

## API Endpoints

| Method | Endpoint | Description |
|--------|----------|-------------|
| GET | `/health` | Model artifact status |
| GET | `/api/v1/symptoms` | 132 canonical symptom IDs |
| GET | `/api/v1/diseases` | 41 supported disease classes |
| GET | `/api/v1/model-info` | Model version, metrics, provenance |
| POST | `/api/v1/predict` | Ranked disease candidates |
| POST | `/api/v1/explain` | SHAP explanation for a disease |

### Example: Predict

```bash
curl -X POST http://localhost:8181/api/v1/predict \
  -H "Content-Type: application/json" \
  -d '{"reported_symptoms": ["high_fever", "headache", "joint_pain", "skin_rash"], "top_k": 5}'
```

### Example: Explain

```bash
curl -X POST http://localhost:8181/api/v1/explain \
  -H "Content-Type: application/json" \
  -d '{"reported_symptoms": ["high_fever", "headache", "joint_pain", "skin_rash"], "target_disease": "Dengue"}'
```

## Key Design Decisions

1. **Feature order safety**: The canonical `feature_names` list in `model_metadata.json` is the single source of truth for vector construction. The API always builds the 132-dim vector using this list, preventing silent prediction errors from feature misalignment.

2. **Calibration flag**: Calibration is active (`calibrated_isotonic`). If calibration is degraded, the API reports `uncalibrated_raw` and the UI shows a warning badge.

3. **SHAP safety framing**: Every explanation response includes an `explanation_note` clarifying that SHAP values explain model behaviour, not clinical causality.

4. **No symptom persistence**: No request body or symptom history is logged or stored.

5. **Error states**: All UI states (loading, success, invalid input, backend offline, model unavailable, explanation unavailable) are explicitly handled.

## Research Limitations

- The model was trained on a controlled, synthetic disease dataset — **not real patient records**.
- Perfect validation accuracy (100%) on the training protocol is a known characteristic of this dataset and does not imply real-world clinical utility.
- ECE of 0.0575 post-calibration indicates good probability calibration on the held-out set but should not be interpreted as real-world diagnostic confidence.
- SHAP explanations reflect model feature importance, not clinical diagnostic reasoning.
